## Strict score definitions and decision rules

1. **Primary independent normal-client FPR denominator = # source-disjoint externally authored client organizations with original client executed and matched raw native `tools/call` response + original downstream observed in-band status under declared policy.** Planned `n=2` (N1/N2), **measured eligibility `m` must be established separately**. False positive `k` is a B38 discrepancy on known correct normal consumer behavior, not an alarm under knowingly wrong contract. Report `k/m`, Wilson 95% interval only when `m>0`, and no ecosystem generalization; if `m=0` explicitly `UNMEASURED`, never 0/2.
2. Negative source cases from P1 may be paired normal controls but **do not** increase independently sourced normal denominator.
3. A positive generic detector hit needs original pre/post pair, same native in-band tool error and observed upstream semantics; pre B38 discrepancy, post no discrepancy. If original official regression RED/GREEN is reproduced but no compatible native wire-to-outcome pair, positive is only `OWNER_REPAIR_REPRODUCED`, no B38 sensitivity claim.
4. Original transport and client/library native peers are not automatically a deployed original application. Report source tier, tested channels, matched request id, original code commit/blob and any test-only overlay, true source revision, execution commands, stdout and artifact hashes.
5. Keep unsuccessful attempts in record; do not select new cases based on failed results. All B41 cases become exposed development cases after analysis, and any tuned algorithms must face fresh source-disjoint B42.
6. **Success goal** (not post-result guarantee): at least 2 original client orgs with valid native matched normal status and at least one original pre/post known true status-as-success positive. If only one original client qualifies, report `m=1` with descriptive Wilson bound (very wide); no false precision.
