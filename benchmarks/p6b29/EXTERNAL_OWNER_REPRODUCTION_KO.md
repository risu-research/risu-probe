# B29 실제 외부 소유자 평가 | 안전한 협력 절차

**현 상태: 준비 완료, 외부 소유자의 실제 승인 미확보.** B29는 사용자 계정 두 개를 만들어 독립성을 가장하는 실험이 아니라, 리소스를 실제로 운영하는 **다른 사람/기관**이 자체 권한으로 승인·거부하고 원본 효과를 확인하는 실험이다.

## 무엇을 확보해야 하는가

외부 연구자, 프로젝트 관리자, 또는 자신이 관리하는 테스트 저장소·DB를 가진 협력자가 적합하다. GitHub 계정만 다른 RISU 내부 관리자는 여기서 원하는 외부 독립 소유자가 아니다. 협력자는 실제 서비스에 영향을 주지 않는 **일회성 테스트 자원**만 사용하며, 개인 비밀번호·API 비밀키·운영 토큰을 RISU에 전달하지 않는다.

다음 조건을 한 번에 충족하는 실험을 목표로 한다.

1. 협력자가 직접 소유하고 관리하는 별도 GitHub 저장소 또는 별도 자원 서비스가 있다. 소유 관계는 해당 서비스가 발행한 원본 관리 권한과 리소스 ID로 확인한다.
2. 협력자가 정확히 어떤 객체에, 어떤 사전 값에서, 어떤 최종 내용을, 몇 번, 언제까지 변경하도록 허락하는지 **자기 쪽** 원본 자료로 고정한다.
3. 요청자와 승인자는 다른 실제 사람이다. 요청자가 승인한 것처럼 꾸민 GitHub 계정·리뷰는 사용하지 않는다.
4. GitHub Actions를 사용하는 경우 협력자의 저장소 Settings → Environments에서 **별도의 테스트 환경**을 구성한다. Required reviewers에 실제 협력자의 계정을 지정하고 Prevent self-review를 활성화한다. 관리자 보호 규칙 우회도 비활성화하고, 허용 브랜치를 제한한다. 기존 B25 환경을 변경해 기존 증거를 손상시킬 필요는 없다.
5. 해당 테스트 리소스에 대한 직접 쓰기 권한은 외부 소유자가 관리한다. 권한 발급은 그 사람이 직접 수행하거나, 소유자 측의 신뢰된 절차에서 실행한다. RISU에 모든 자원에 대한 무제한 토큰을 전달하지 않는다.
6. 비신뢰 실행자는 자신에게 발급된 최소 권한으로 정식 요청과 경로·내용·반복·철회 우회를 시도한다. 원본 리소스 서비스가 실제로 거부하거나 허용하는지 관찰한다.
7. 소유자 본인이 별도 원본 기록을 조회해 승인 전후 데이터·변경 이력·권한 회수 여부를 확인한다. 원본 승인과 원본 효과가 동일 저장소/실행/요청 해시에 연결되어야 한다.

## GitHub에서 보호해야 할 경계

- 보호되지 않은 새 GitHub Actions 환경을 자동으로 생성하면, 아무도 승인하지 않아도 작업이 진행될 수 있다. **먼저** 보호 환경을 설정하고, **그 다음** 워크플로를 실행해야 한다.
- 자원 테스트 저장소의 기본 브랜치 및 테스트 파일도 별도 branch protection/ruleset으로 직접 변경을 막아야 한다. Required reviewer는 환경의 작업 실행을 제한할 뿐, 그 자체로 GitHub 저장소 쓰기 권한을 특정 파일에 한정하지 않는다.
- 기본 GitHub Actions GITHUB_TOKEN의 contents:write는 일반적으로 저장소 범위 권한이다. 이는 파일별/내용별 권한 자체가 아니다. 경로·변경 내용 조건은 신뢰 코드, 브랜치 보호 또는 원본 자원 서비스가 별도로 집행해야 한다.
- 초대가 필요한 경우 별도 협력자가 실제로 의사를 밝히고 자신의 계정으로 조치해야 한다. RISU가 임의로 두 번째 계정을 만들어 승인 기록을 만들면 연구 목적을 충족하지 못한다.
- 외부 소유자 승인 직후 직접적인 무단 요청, 정확한 승인 내용, 철회 후 새 요청을 분리 검증한다.

## 실제 진행할 때 필요한 자료

협력자가 제공할 것은 테스트에 동의했다는 사실과 자신이 운영하는 **테스트 자원 주소 또는 GitHub 공개 저장소 링크**다. 이후 승인·실행은 소유자가 자신의 GitHub/서비스 UI에서 직접 수행한다. 비밀키와 비밀번호를 요구하거나 보낼 필요는 없다.

RISU 측 B29 read-only 도구 예:

    risu-probe verify-mcp-independent-owner \
      --repo OWNER/REPOSITORY \
      --run-id RUN_ID \
      --environment ENVIRONMENT_NAME \
      --effect-repo OWNER/REPOSITORY \
      --effect-run-id SAME_RUN_ID \
      --out owner-audit.json

이 결과가 성공해도 입증되는 것은 우선 **서로 다른 GitHub 계정의 원본 승인이 동일한 실행에 속한다는 것**이다. 실제로 별개의 자연인인지, 그 승인이 자원 소유자의 법적·운영 권한에 근거했는지, 원본 데이터가 정확히 변경됐는지는 외부 소유자의 별도 증거로 평가한다.

## 지금까지 확보된 증거와 부족한 증거

- B25: 실제 GitHub 사람 승인 및 정확한 원본 파일 변경을 검증했음. 승인자와 실행 시작자는 동일 계정.
- B28: 독립 개발 조직의 OpenBao 및 PostgreSQL에서 진짜 발급·실행·철회와 독립 감사를 검증했음. 서버와 테스트 계정은 RISU 관리.
- B29: 두 기록을 섞어 거짓으로 독립 소유자를 인증할 수 없음을 **실제 GitHub API**에서 실증하고, RISU 검증기를 설치형 세 OS에서 전수 회귀했음.
- **다음 긍정 실험에는 실제 외부 소유자의 독립 승인과 소유자 쪽의 리소스 효과 증거가 필요함.** 필요한 승인 없이 성공했다고 쓰지 않는다.

## 안전한 선택

실제 운영 중인 고객 시스템이나 다른 사람의 데이터를 건드리지 말고 협력자가 만든 샌드박스 한 개로만 검증한다. 협력 여부는 상대방의 자발적 동의에 달려 있으며, 협력 요청 메시지는 사용자가 직접 보내도록 남겨 둔다. 프로젝트나 연구소 이름으로 승인을 대신하지 않는다.
