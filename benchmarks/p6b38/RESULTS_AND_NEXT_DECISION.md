## Source-independent verifier bounds and negative controls

The B38 verifier input must contain a native request/response pair with matching request ID and tool name, explicit observed consumer status, plus an externally chosen contract `status: true` and optionally `text/structured/media: "exact"`. It compares actual `isError` vs consumer outcome, text equality, exact structured JSON equality, and digest of actual image/audio base64. It requires the evidence to be present; unknown or incompatible modes fail as `INCOMPLETE` rather than clean pass or a false positive. Real JSON-RPC errors remain separate from MCP application failures. Original before/after Git commit/blob assertions are enforced by collectors; the checker output records declared origin/provenance but Git objects are not independent execution attestations. Explicit summarization, redaction, model-host visibility choices or intentional media notices require their own *different* contracts. Unit tests (26) are NOT a sample of normal independent external adapter prevalence; a general-population false positive rate remains `UNMEASURED`.

## What to do next

1. Keep the frozen B38 results and **do not tune against B38 then re-label these cases independent**. Evaluate unexecuted original TypeScript clients (DeepSeek Harness/Claude Mem) and OpenClaw only as *post-seal additional setup*, with honest classifications and canonical original logs.
2. Prioritize a **runtime-first product workflow** using controlled low-privilege MCP test server + real upstream client tool call and an observed downstream result. Record expected channels *before* running the test, rather than determining expected values after observing outputs; real use requires a trustworthy consumer-outcome witness.
3. Strengthen **independent normal original adapters** with negative controls for intentional summaries, redactions, media notices, error-handled normal completions, and differences among protocol versions. Report false-positive rate only within that defined, actually measured normal cohort, including uncertainty.
4. Freeze a new B39 external runtime holdout before changing checker semantics or score rules. Track status/text/media/structured channels separately and differentiate actual third-party client execution from isolated functions, original parsers and first-party synthetic tests.
5. **Keep public main unchanged** until opt-in runtime verifier shows real user value beyond controlled retrospective issues, can document reproducible false-positive behavior, safe invocation and trustworthy evidence collection. Avoid making unsupported ecosystem-wide recall or claiming discovery of bugs already fixed by maintainers.
