# P6-B38 preregistration | Runtime-first semantic contract verification

**Commit before any B38 source code was read or adapted.** Case selection uses already merged public PR issue summaries, changed filenames, first parent and exact source blob identifiers only.

## Objective

Test whether the *preexisting B37 runtime error-semantics verifier* (source-independent JSON-RPC request/response identity, `isError`, observed consumer success/error, native error reason, and normal controls) generalizes to NEW real independently authored upstream clients. Keep distinct result cohorts for source-only, original upstream execution with controlled producer, and run-without-upstream. Original upstream runtime should be preferred, but impossibility or dependencies must be reported, not disguised as a negative result.

## Immutability and eligibility

- Eight merged external fixes from distinct organizations, none used in B34/B35/B36/B37; one pre-fix first-parent commit and one merge-fix commit for each. Source path and Git blobs presealed. Original after-only files do not replace nonexistent before files. Any exact source blob mismatch is `UNVERIFIED`, not a replacement opportunity.
- No B38 source inspection prior to the seal and the frozen verifier reference. Existing B37 verifier original code `research/b37_protocol_error_effect_auditor.py` from `qualification/p6b37-native-original-kitagent-20261113@c272114d3c824b29324ed2bb086981aee9fb8c5e`. This rule focuses on application-error status across real MCP native JSON-RPC and does not assert other-channel preservation.
- Precommitted primary runtime cohort: before-after **independent original upstream client code with actual MCP JSON-RPC observed on stdio or HTTP** and the same credential-free controlled test producer for both original versions. A program run against a mocked SDK object without actual wire is `SDK_UNIT_ONLY` and not a native runtime outcome. Pure original parser unit tests are `PARSER_ONLY`. Dataset includes clients, transports, servers and parsers; each type has its own denominator and NEVER contributes to cross-type sensitivity claims.
- Runtime status-positive means a native wire tool-result `isError=true` reached a consumer as `success`, while a paired original fixed consumer reports tool error; normals, JSON-RPC errors and request/tool correlation pass. Explicitly contract expected projection of result. Other types: `STRUCTURED_ONLY_PROJECTED_EMPTY`, `MULTIMODAL_BLOCK_LOSS`, `DUPLICATE_STRUCTURED_PAYLOAD` only if both native wire and recorded consumer outcome are obtained, and separately audited under a **pre-frozen new rule**. Otherwise `NOT_TESTED_SEMANTIC_FAMILY`.
- Selected original source wrappers and dependency installation may be written after the seal but are **execution adapters**, not proof of untouched detector generalization: report adaptation per case and whether any source patching, monkeypatching or test fixtures occur. Never modify pinned original source without recording exact transformations; if adapter modifies semantic logic, disqualify from original execution.
- For every enabled original client, run before+after with same producer and expected protocol version and six preselected controls: valid single text, `isError=true` with content, empty error, multiple text blocks, JSON-RPC error, and valid normal call after a failure. For structured-only cases additionally provide `structuredContent` and empty blocks. Counterexample where intentional summarization/redaction is permitted must NOT be flagged for “loss” unless contract requires preservation.
- Report results per original organization and per *mechanism*, including all misses, unexecuted/unsupported and incomplete cases. The eight PRs represent purposively selected fixes and do not yield population sensitivity or false positive rate.
- The B37 already-fixed KitAgent source is the **development reference only**. No B38 case may be used to tune the verifier prior to the first sealed run; if integration adapters are adjusted after inspecting original code, publish that as post-seal setup and never claim an unassisted blind integration score.
- CI must record full original commit SHA, Git tree and blob sha, native raw JSONL and content hashes, consumer observable values, verifier outcome, a test-level provenance classification, and normal control results, across Linux/Windows/macOS where feasible. Do not execute upstream third-party servers with unknown authority, credentials, or internet by default.
- Published `risu-probe/main` must not change until independent false-positive controls and external developer utility are established. B38 retrospective results become development data after their first observation; future tuning requires sealed untouched B39.

## Criteria for claiming genuine progress

The existing checker finding another independently maintained original consumer's protocol application-error misclassification at runtime, with raw native wire trace and a correct official repaired control, would demonstrate **cross-organization mechanism generalization** beyond B37. Failing to execute or reproduce must be reported clearly. Genuine external original server behavior is a separate evidence level. A detector that passes only synthetic controls adds no independent generalization evidence.
